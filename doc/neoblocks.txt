INTRODUCTION                                                 *neoblocks-intro*

Hand-rolled replacements for Neovim plugins.

One module per plugin it replaces, each off until `setup()` names it. `Neoblocks.<module>` loads a module on
first use, so a module you don't use is never loaded.

A module that's on can be switched off and on again:
- everywhere: `:Neoblocks {module} {on|off|toggle}`, `vim.g.neoblocks_<module> = false`;
- in one buffer: `:Neoblocks! {module} {on|off|toggle}`, `vim.b.neoblocks_<module> = false`. A buffer's switch
  wins over the global one.

Neoblocks.setup({opts})                                    *Neoblocks.setup()*
    Turns on each module named in `opts`, unless its options say `enabled = false`.

    >lua
      require("neoblocks").setup({ colors = {} })
    <

    Parameters: ~
      • {opts} (`neoblocks.Config`)

Neoblocks.toggle({name}, {state}, {buf})                  *Neoblocks.toggle()*
    Turns a module on or off without losing its setup: globally, or in one buffer.

    Parameters: ~
      • {name} (`string`)
      • {state} (`boolean`) on or off; flips it when nil
      • {buf} (`integer`) a buffer (0 for the current one); all buffers when nil

DIAGNOSTICS                                            *neoblocks-diagnostics*

Diagnostics in a pill after the cursor's line, counts elsewhere (replaces tiny-inline-diagnostic)

tiny-inline-diagnostic's look, drawn by a `vim.diagnostic` handler (`:h diagnostic-handlers`). Replaces
[tiny-inline-diagnostic.nvim](https://github.com/rachartier/tiny-inline-diagnostic.nvim) set up with its "modern"
preset, messages, counts, multiline and related information:

- the cursor's line: its diagnostics after the text in a rounded pill tinted by severity: the ones under the cursor,
  or every one on the line when none is. Each message line gets a row of its own below (`│`, `└`), with LSP related
  information under its diagnostic (`↳`). When the line ends too close to the window's edge, they go under it;
- when the cursor's line has none, each visible line with diagnostics gets a small pill: a `●` per diagnostic,
  coloured by severity, and their count;
- nothing in Insert, Visual or Select mode, nor while `vim.diagnostic.open_float()`'s float is open.

>lua
  vim.diagnostic.config({ virtual_text = false }) -- this draws them instead
  require("neoblocks").setup({ diagnostics = {} })
  vim.keymap.set("n", "<leader>dt", function() Neoblocks.toggle("diagnostics") end, { desc = "Inline diagnostics" })
<

`setup()` adds the `neoblocks.diagnostics` handler and turns it on in `vim.diagnostic.config()`, so the built-in
switches work on it as on the built-in handlers: `vim.diagnostic.enable(false)` hides it, `vim.diagnostic.config({
["neoblocks.diagnostics"] = false })` turns it off, and `vim.diagnostic.config({ ["neoblocks.diagnostics"] = {
severity = ... } })` filters what it draws. It draws every buffer with diagnostics, from LSP or not.

The colours come from `DiagnosticError`, `DiagnosticWarn`, `DiagnosticInfo`, `DiagnosticHint`, `CursorLine`,
`NonText` and `Normal`, blended again on `ColorScheme`, into the `NeoblocksDiagnostics*` groups. The signs are Nerd
Font glyphs, as the preset's are.

Options ~                                      *neoblocks-diagnostics-options*
>lua
  ---@class neoblocks.diagnostics.Config
  ---@field show_source? boolean add each diagnostic's source, as `(source)`
  ---@field show_code? boolean add each diagnostic's code, as `[code]`
  ---@field related? integer how many LSP related-information entries to show under each diagnostic; 0 for none
  ---@field softwrap? integer the cursor line's diagnostics go under it when it ends this close to the window's edge
  ---@field blend? number how much of the severity's colour tints the pill, from 0 to 1, over `Normal`'s background
  ---@field priority? integer the extmarks' priority: higher draws over other virtual text
  ---@field hide_on_float? boolean hide them while `vim.diagnostic.open_float()`'s float is open
  local defaults = {
    show_source = true,
    show_code = true,
    related = 3,
    softwrap = 30,
    blend = 0.22,
    priority = 2048,
    hide_on_float = true,
  }
<

Neoblocks.diagnostics.refresh({buf})         *Neoblocks.diagnostics.refresh()*
    Draws again after the module is switched on or off: a buffer (0 for the current one), or every buffer.

    Parameters: ~
      • {buf} (`integer`)

FASTAPI                                                    *neoblocks-fastapi*

FastAPI routes in a picker, read from the code (replaces fastapi-vscode's route search)

A FastAPI project's routes in a picker, found by reading the code, never by running it. Replaces the path
operation search of [fastapi-vscode](https://github.com/fastapi/fastapi-vscode), ported from its analyzer:

- the apps: `entrypoint` if set, else `[tool.fastapi] entrypoint` in a pyproject.toml, else every app assigned in a
  file that calls `FastAPI(`; test files, `tests/` and hidden folders aren't searched;
- their routes: each `@app.get(...)`, `@router.post(...)`, `@app.api_route(...)` and `@app.websocket(...)`, with
  the prefixes of the `include_router()` and `APIRouter(prefix=...)` above it and the path of a `mount()`, followed
  through imports, `__init__.py` re-exports, namespace packages, a `src/` layout and factory functions;
- a path built from string constants, f-strings and `+` resolves; another expression stays as `{expression}`, and
  the picker leaves out the leading ones (`{settings.API_V1_STR}/users` shows as `/users`).

>lua
  require("neoblocks").setup({ fastapi = {} })
  vim.keymap.set("n", "<leader>sF", function() Neoblocks.fastapi.pick() end, { desc = "FastAPI routes" })
<

In [snacks.nvim](https://github.com/folke/snacks.nvim)'s picker: `<CR>` opens the handler, `<a-g>` where its
router or app is made, `<a-y>` yanks its path, `<c-q>` sends the list to the quickfix list. Its source is
`fastapi_routes`, so `picker.sources.fastapi_routes` in snacks' options changes it. Without snacks, the routes are
offered in `vim.ui.select()`.

Python is read with tree-sitter: it needs the `python` parser (`:TSInstall python` with nvim-treesitter); a file
is read again only once it changed, and an unsaved buffer counts with its edits. Methods are drawn in
`NeoblocksFastapiGet`, `...Post`, `...Put`, `...Patch`, `...Delete`, `...Options`, `...Head` and `...Websocket`,
linked to diagnostic colours as Swagger UI colours them; a deprecated route's path in `NeoblocksFastapiDeprecated`.

Options ~                                          *neoblocks-fastapi-options*
>lua
  ---@class neoblocks.fastapi.Config
  ---@field entrypoint? string the app, as `package.module:variable` from the current directory; default: pyproject.toml's `[tool.fastapi] entrypoint`, else every app
  ---@field exclude? string[] folder names not searched for apps, besides hidden ones
  local defaults = {
    entrypoint = nil,
    exclude = { "venv", "__pycache__", "node_modules", "tests", "test" },
  }
<

Neoblocks.fastapi.setup()                          *Neoblocks.fastapi.setup()*
    Reads the options and defines the highlight groups.

Neoblocks.fastapi.routes()                        *Neoblocks.fastapi.routes()*
    Every route of the project in the current directory, sorted by path as the picker shows it, then by method.
    Raises an error when there's no Python parser, or the entrypoint names no file or no app.

    Return: ~
      (`neoblocks.fastapi.Route[]`)

Neoblocks.fastapi.pick()                            *Neoblocks.fastapi.pick()*
    The routes in snacks' picker, or `vim.ui.select()` without it: `<CR>` opens the handler, `<a-g>` the router or app,
    `<a-y>` yanks the path. Says why instead when the module is switched off or there are no routes.

MESSAGES                                                  *neoblocks-messages*

ui2 with noice's cmdline popup, toasts and long output in a split (replaces noice.nvim)

noice.nvim's message and cmdline look on top of Neovim's own ui2 (`:h ui2`), with nothing drawn by a UI of its
own. Replaces [noice.nvim](https://github.com/folke/noice.nvim) for its command_palette, bottom_search and
long_message_to_split presets with [snacks.nvim](https://github.com/folke/snacks.nvim)'s notifier:

- `:` and `input()` prompts in a bordered popup near the top, titled by the kind of command (Cmdline, Lua, Help,
  Filter, Calculator or the prompt); blink.cmp's cmdline menu opens under it (`vim.g.ui_cmdline_pos`);
- `/` and `?` over the last row, so the windows don't move;
- messages as snacks.notifier toasts, each staying as long as snacks' `timeout` and `notifier.keep` say;
  info merges into one toast; output taller than a toast opens in a split below that isn't entered (`q` closes it);
  undo, quickfix, completion and verbose messages are left out, as noice left them out;
- `history()`: every message since startup in a picker, newest first;
- `showcmd()`: the keys of a command that waits for more (a count, `d`, `g`), for a statusline, without the one-frame
  flash of keys whose command runs at once (`w`, `j`, `^D`).

>lua
  vim.o.cmdheight = 0 -- the popup and the bottom search need it, as noice's do
  require("neoblocks").setup({
    messages = {
      -- messages ui2 keeps in its float, a typed command's output in the cmdline
      ui2 = { msg = { targets = { default = "msg", typed_cmd = "cmd" } } },
    },
  })
  vim.keymap.set("n", "<leader>n", function() Neoblocks.messages.history() end, { desc = "Message history" })
<

Call `setup()` early in your config, before any message you want to see as a toast: `setup()` turns ui2 on with
the `ui2` options unless your config already did (`require("vim._core.ui2").enable()`), then hooks it. What comes
before that stays with plain ui2. Errors and warnings ui2 showed before snacks.notifier was set up become toasts
once it is, on the tick after UIEnter (lazy.nvim's VeryLazy), or at VeryLazy itself.

snacks.nvim is optional and found at runtime: without its notifier, messages stay with ui2 (and still go in the
history); without its picker, `history()` lists them in a split. ui2 is private (`vim._core`): each part checks the
internals it hooks when it's set up, and a part that finds one missing, or fails while it runs, puts ui2's own
handler back and says so once, so a Neovim that renamed one gives plain ui2, not a broken cmdline. Checked on
Neovim 0.13 nightly; `:checkhealth neoblocks` shows which parts are on. Without a UI attached
(`--headless`) there's no ui2, and the module does nothing.

The popup's border, title and icon are drawn in `NeoblocksMessagesBorder`, `NeoblocksMessagesTitle` and
`NeoblocksMessagesIcon`, linked to `DiagnosticSignInfo` (noice's colour). A toast passes `routine = true` to
snacks for a routine error (a search or jump that found nothing), so a snacks `notifier.keep` that holds errors
until dismissed can let the routine ones time out:

>lua
  require("snacks").setup({
    notifier = { keep = function(n) return n.level == "error" and not n.routine or vim.fn.getcmdpos() > 0 end },
  })
<

Options ~                                         *neoblocks-messages-options*
>lua
  ---@class neoblocks.messages.Config
  ---@field ui2? table options for `require("vim._core.ui2").enable()`, when `setup()` turns ui2 on itself
  ---@field cmdline? boolean `:` and `input()` in the popup, `/` and `?` over the last row
  ---@field toasts? boolean messages as snacks.notifier toasts and long output in a split; false leaves them to ui2
  ---@field showcmd? boolean pending keys through `showcmd()`, which sets 'showcmdloc'; false leaves 'showcmdloc' alone
  local defaults = {
    ui2 = {},
    cmdline = true,
    toasts = true,
    showcmd = true,
  }
<

Neoblocks.messages.setup()                        *Neoblocks.messages.setup()*
    Turns ui2 on unless it is, then hooks each part the options turn on.

Neoblocks.messages.refresh({buf})               *Neoblocks.messages.refresh()*
    After `:Neoblocks messages off` the cmdline and messages go back to plain ui2, and pending keys to Neovim's own
    `%S` ('showcmdloc' "statusline"); on again, to this module.

    Parameters: ~
      • {buf} (`integer`)

Neoblocks.messages.entries()                    *Neoblocks.messages.entries()*
    Messages seen since `setup()`, oldest first: the toasts, the split's output and what ui2 kept (route "ui2").

    Return: ~
      (`neoblocks.messages.Entry[]`)

Neoblocks.messages.history()                    *Neoblocks.messages.history()*
    The message history, newest first, like noice's `:Noice history`: the messages of `entries()` and, with
    snacks.notifier, the `vim.notify()` calls it shows. In a snacks picker, filterable by level, title and text; without
    snacks, listed in a split (`q` closes it). `g<` and `:messages` still open ui2's pager.

Neoblocks.messages.pending()                    *Neoblocks.messages.pending()*
    The keys typed so far of a command that waits for more (a count, an operator, `g`, a register), last 10
    characters; empty while none waits. A lone key whose command runs at once is left out.

    Return: ~
      (`string`)

Neoblocks.messages.showcmd()                    *Neoblocks.messages.showcmd()*
    Pending keys as statusline text: `pending()` while the module is on, Neovim's own `%S` while it's switched off or
    the hook isn't in (a ui2 without it). For that the module sets 'showcmdloc': "last" while on, so the keys reach the
    hook, "statusline" otherwise, so Neovim draws them. The text is the same either way, so a statusline drawn once
    follows a switch. For a statusline component: `function() return Neoblocks.messages.showcmd() end`.

    Return: ~
      (`string`)

STATUSLINE                                              *neoblocks-statusline*

A global statusline rebuilt only on events (replaces lualine.nvim)

A global statusline built from two lists of components, rebuilt on events and never on a cursor move. Replaces
[lualine.nvim](https://github.com/nvim-lualine/lualine.nvim) for a statusline with one global line.

>lua
  {
    "AH-Merii/neoblocks.nvim",
    event = "VeryLazy",
    config = function()
      local sl = require("neoblocks.statusline")
      require("neoblocks").setup({
        statusline = {
          color = { fg = "#abb2bf" },
          left = {
            { function() return "" end, color = sl.mode_color({ i = { fg = "#98c379" } }), padding = { right = 1 } },
            "%f",
            { "diagnostics", symbols = { error = "E" } },
            "%=",
          },
          right = {
            { "branch", icon = "", color = { fg = "#56b6c2", bold = true } },
            "diff",
            "searchcount",
            { "%3l:%-2c", color = { bold = true } },
          },
        },
      })
    end,
  }
<

A component is a function returning statusline text, a statusline string starting with `%`, a built-in name
(`diagnostics`, `branch`, `diff`, `searchcount`, `progress_status`, `recording`) or a table with one of those
first and its options. A component draws nothing when it's empty or its `cond` isn't true; otherwise
`icon text` with one space each side (`padding`), as lualine draws it.

A colour is a highlight group name or a table of `nvim_set_hl()` attributes, e.g. `{ fg = "#e5c07b", bold = true }`
(lualine's `gui = "bold"` is `bold = true` here). A colour Neovim rejects is reported and drawn in the default one.

Text from a function or a string goes in as statusline text, unescaped, so `%l`-style items and `%{...}`
expressions in it follow the cursor without a rebuild; text that isn't valid statusline syntax is reported and its
component left out. The line is rebuilt on `events` and the events the built-ins in use need, at most once per
16 ms, and at once by `refresh()`. A cursor move runs nothing, except while a search is highlighted and the line
has `searchcount`: then it counts the matches again, at most once per 16 ms. `diff` shows gitsigns.nvim's counts.

Options ~                                       *neoblocks-statusline-options*
>lua
  ---@class neoblocks.statusline.Config
  ---@field left? neoblocks.statusline.Component[] drawn from the left edge; a "%=" entry starts a centred group
  ---@field right? neoblocks.statusline.Component[] drawn against the right edge
  ---@field color? neoblocks.statusline.Color text colour of components without their own; default StatusLine's
  ---@field events? string[] events that rebuild the line; built-ins add their own
  ---@class neoblocks.statusline.ComponentOpts
  ---@field [1] string|fun(): string? a function, a "%..." statusline string, or a built-in name
  ---@field icon? string drawn before the text, with a space; left out with the text when it's empty
  ---@field color? neoblocks.statusline.Color|fun(): neoblocks.statusline.Color? called on each rebuild
  ---@field cond? fun(): boolean drawn only when it returns true
  ---@field on_click? fun(clicks: integer, button: string, mods: string)
  ---@field padding? integer|{ left?: integer, right?: integer } spaces around the text: 1 each side by default
  ---@field symbols? table<string, string> diagnostics: error/warn/info/hint; diff: added/modified/removed
  ---@field diagnostics_color? table<string, neoblocks.statusline.Color> diagnostics: a colour per severity
  ---@field diff_color? table<string, neoblocks.statusline.Color> diff: added/modified/removed colours
  local defaults = {
    left = { "%f %m%r", "branch", "diff", "diagnostics" },
    right = { "searchcount", "recording", "progress_status", "%l:%c" },
    events = {
      "WinEnter",
      "BufEnter",
      "BufWritePost",
      "SessionLoadPost",
      "FileChangedShellPost",
      "VimResized",
      "FileType",
      "ModeChanged",
    },
  }
<
